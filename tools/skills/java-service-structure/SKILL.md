# Java 服务结构

仅在 Java 项目中使用，并以现有包结构和架构文档为准；本 skill 不要求项目采用特定框架或目录名。

## 职责与依赖

保持依赖从协议入口流向用例编排、规则/查询支持/转换/客户端，再到持久化；低层组件不得反向依赖具体用例实现。

| 职责 | 建议边界 | 不应承担 |
|---|---|---|
| 协议入口 | 请求校验、调用、标准响应 | 持久化、锁、事务脚本、远程协议细节 |
| 用例服务 | 上下文、权限、分支和步骤编排 | 大量字段转换、原始 SQL、供应商 HTTP |
| 纯规则 | 无 I/O 的校验、计算、状态推导 | Mapper、远程调用、事务编排 |
| 查询支持 | 有界读取、批量补全、读模型组装 | 写事务、协议响应包装、无关工具 |
| 事务执行器 | 一个明确原子一致性集合 | 权限、分布式锁、响应组装 |
| 客户端/适配器 | 协议、防腐转换、远程错误映射 | 本地状态机、事务所有权 |
| 转换器 | 确定性字段映射 | 查询、当前时间、权限、业务写入 |

## 提取与方法设计

- 只有出现可命名且可测试的独立职责、已有调用边界或确定复用需求时才提取类。
- 用例编排保持“上下文 -> 校验 -> 查询 -> 锁 -> 事务 -> 响应”的可读顺序；复杂步骤拆成意图明确的私有方法。
- 相关参数超过 3 个且跨边界传递时，优先使用不可变 `record`；不得将 `Optional` 用作字段或参数。
- 无依赖、无状态、无 I/O 的规则可使用静态方法；需要时钟、配置、国际化、持久化或客户端的规则必须保留依赖注入。
- 复用现有转换工具或 MapStruct；一次性简单映射不必新增转换器。

## 注释与复核

核心类和超过 10 行的核心方法补充与项目风格一致的 Javadoc。行注释解释锁顺序、CAS、时间边界、租户切换或部分成功等“为什么”，不复述赋值语句。

完成后检查：职责是否单一、依赖是否单向、是否新增了无必要抽象，以及测试是否覆盖提取后的边界。
